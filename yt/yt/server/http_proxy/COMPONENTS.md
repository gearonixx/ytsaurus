## Основные (понять в первую очередь)

● Нет, прокси отдаёт в нескольких форматах: json, yson (родной формат YT, бинарный/текстовый), dsv, yamred_dsv, pretty и т.д. Клиент выбирает заголовком X-YT-Output-Format или Accept. JSON удобен для        
веба/скриптов, YSON — для нативных YT-клиентов и табличных данных, остальное — для legacy-MapReduce-форматов.

- `bootstrap` — корень процесса: создаёт и владеет всеми компонентами, поднимает HTTP/HTTPS-серверы, запускает их в `DoStart`.
- `api` — обработчик `/api/*`: семафоры на параллельность, лимиты по юзерам, метрики, проверка бана; делегирует команду в драйвер через `TContext`.
- `context` — стейт обработки одного запроса: парсинг URL/заголовков, аутентификация, выбор формата ввода/вывода, вызов драйвера, потоковая передача тела ответа.
- `coordinator` — регистрация прокси в Cypress (`//sys/proxies/...`), публикация её роли (control/data), отслеживание соседних прокси для балансировки.
- `http_authenticator` — превращает HTTP-заголовки/куки в YT-юзера: дёргает токен/cookie/TVM-аутентификаторы из `auth_server`.
- `config` — определения структур конфига (статического `TProxyBootstrapConfig` и динамического `TProxyDynamicConfig`).

## Вспомогательные

- `program` — `main()` бинаря `ytserver-http-proxy`: парсит CLI-флаги, создаёт `TBootstrap`, вызывает `Run()`.
- `access_checker` — проверяет, имеет ли юзер право ходить через эту конкретную прокси (отдельно от Cypress-ACL'ов на объекты).
- `dynamic_config_manager` — читает динамическую часть конфига из Cypress и оповещает подписчиков при её обновлении.
- `formats` — выбор формата сериализации тела (`json`/`yson`/`pretty`/...) на вход и выход по заголовкам/параметрам.
- `framing` — потоковый «фреймовый» протокол YT поверх HTTP: дробит большой ответ на куски с заголовками длины, чтобы клиент мог стримить.
- `helpers` — мелкие утилиты, общие для контекста и api (CORS-хелперы, парсинг параметров и т.п.).
- `component_discovery` — собирает список живых компонентов кластера (мастеры, ноды, прокси) с версиями для эндпоинта `/internal/discover_versions`.
- `solomon_proxy` — проксирует запросы метрик к Solomon-агентам других прокси, чтобы внешний пул собирал всё через один эндпоинт.
- `profiling` / `profilers` — счётчики и аллокационные теги для метрик прокси (`request_count`, `bytes_in/out`, разрезы по user/command), плюс heap profiler.
- `private` / `public` — типовые YT-файлы: `public` объявляет публичные типы и `Ptr`-алиасы, `private` — внутренние логгеры/константы.
- `clickhouse/handler` (в подпапке) — отдельный обработчик эндпоинтов CHYT (`/query`, `/chyt`), реализующий ClickHouse-протокол поверх YT.
