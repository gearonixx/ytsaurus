
 FromProto<T>(x) — это конвенция YT для конвертации значения из protobuf-представления в C++-тип T. У protobuf свои примитивы (string, bytes, int64…), а в коде живут типизированные обёртки (TGuid, TCellTag,
  
  TTransactionId…), поэтому пишут перегрузки FromProto/ToProto, которые знают, как одно превратить в другое. Здесь rsp->object_id() — это protobuf-сообщение из двух uint64 (high/low), а
  FromProto<TObjectId>(...) собирает из них настоящий TGuid.

  1. Создаём пустой "конверт" для пачки запросов  (batchReq)
  2. На каждый userObject кладём в конверт письмо:
         "мастер, дай мне атрибуты этого пути"
  3. Отправляем конверт на мастер:  WaitFor(batchReq.Invoke())
  4. Мастер у себя ищет путь -> находит объект -> кладёт его ObjectId в ответ
  5. Получаем пачку ответов обратно

Совсем просто:
  
  1. Создаём пустой "конверт" для пачки запросов  (batchReq)
  2. На каждый userObject кладём в конверт письмо:
         "мастер, дай мне атрибуты этого пути"
  3. Отправляем конверт на мастер:  WaitFor(batchReq.Invoke())
  4. **Мастер у себя ищет путь -> находит объект -> кладёт его ObjectId в ответ**
  5. Получаем пачку ответов обратно

  То есть object_id появляется на мастере, пока мы ждём в WaitFor. У клиента до этого момента его нет — есть только путь.
