

Разница с остальными по слоям: Data Node хранит чанки, Tablet Node обслуживает динамические таблицы (точечные чтения/записи, транзакции), Exec Node — массовая пакетная обработка статических таблиц через джобы. Exec Node читает входные данные с Data Nodes, считает, пишет результат обратно на Data Nodes.

---

Не темплейт. K8s-оператор — это программа, которая работает внутри Kubernetes и автоматически управляет сложным приложением (тут — кластером YTsaurus) вместо человека: разворачивает компоненты, следит за их состоянием, обновляет, чинит.

Темплейт (helm-чарт) — просто статичные YAML-манифесты, развернул и всё. Оператор — живой процесс, который постоянно следит за кластером и реагирует: упала нода — поднимет, нужен апдейт — выкатит по правильному порядк


---


  - SuppressAccessTracking — не обновлять время последнего доступа к таблице (на мастере не дёргать «эту таблицу читали»).
  - SuppressExpirationTimeoutRenewal — не продлевать TTL таблицы при чтении (если у неё стоит автоудаление).
  - UnavailableChunkStrategy — что делать, если чанк недоступен: упасть, пропустить, ждать.
  - ChunkAvailabilityPolicy — какой чанк считать «доступным» (например, достаточно одной реплики или нужен кворум).
  - MaxReadDuration — жёсткий таймаут на всё чтение.
  - DynamicStoreReader — отдельный конфиг для чтения из динамических стораджей (для динамических таблиц — это часть данных, которая ещё в памяти tablet node и не сброшена в чанки).
---

 - WindowSize — размер окна prefetch'а ридера: сколько строк/байтов читать вперёд про запас. При 1 — читаем минимум.
  - GroupSize — сколько чанков объединять в одну «группу» для параллельного чтения. При 1 — никакого параллелизма, по одному чанку за раз.
