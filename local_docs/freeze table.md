Freeze = «запрети запись, но чтение оставь». Все накопленные в памяти данные сбрасываются на диск, после этого `insert-rows` не работает, а `select-rows`/`lookup-rows` работают как обычно. Нужно, чтобы спокойно скопировать или забэкапить таблицу, не боясь что в момент копирования прилетят новые записи.


В системах с LSM-tree хранилищем поверх распределённого кластера: HBase (`flush` + `disable`), Bigtable (внутри, через snapshot), Cassandra (`nodetool flush` + `drain`), ScyllaDB. Везде где есть memtable в памяти и нужен консистентный снапшот для бэкапа/копирования — нужен такой механизм.

In memory mode — это режим, который говорит, держать ли данные tablet'а целиком в RAM для быстрого доступа, а не подгружать с диска при каждом чтении.

`In memory mode` — это режим, который говорит, держать ли данные tablet'а **целиком в RAM** для быстрого доступа, а не подгружать с диска при каждом чтении.

Три значения: `none` — обычный режим, данные на диске, читаются по запросу (как у тебя). `compressed` — все чанки tablet'а загружены в память в сжатом виде, чтение не идёт на диск, но при доступе нужна распаковка. `uncompressed` — данные в памяти уже распакованные, самый быстрый lookup, но жрёт больше всего RAM.

Сам по себе freeze в YTsaurus нужен по той же причине, что и в любой LSM-системе: чтобы получить консистентный снапшот для backup/copy/remote-copy без остановки чтений. У YTsaurus это базовая операционная примитивная вещь, ничего экзотического — в твоём логе просто параметр со значением по умолчанию.

LSM (Log-Structured Merge-tree) — это структура хранения данных, где новые записи сначала попадают в память (memtable), а затем периодически сбрасываются на диск в виде неизменяемых отсортированных файлов (SSTables), которые в фоне сливаются (compaction).

`mutation_id` у create/mount — уникальный id операции, который защищает от повторного выполнения при retry. Если запрос отвалился по сети и клиент повторит — мастер увидит тот же `mutation_id` и не создаст таблицу второй раз. У `insert_rows`/`select_rows` его нет, потому что `allow_retries: False` — для tablet-операций ретраи делаются на другом уровне.
