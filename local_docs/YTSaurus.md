**MapReduce** — модель параллельных вычислений над большими данными, где обработка разбита на две фазы:

**Map**: входные данные делятся на куски, и к каждой строке независимо применяется функция, которая выдаёт пары `(ключ, значение)`. Параллелится тривиально — каждый кусок обрабатывает своя джоба, они друг про друга не знают.

**Shuffle** (между фазами, делается фреймворком): все промежуточные пары перегруппировываются по ключу — все значения с одинаковым ключом собираются вместе, возможно на другой машине.

**Reduce**: для каждого ключа вызывается функция, которая получает все его значения и сворачивает их в результат (сумма, среднее, список, что угодно).

Классический пример — word count: map выдаёт `(слово, 1)` для каждого слова в тексте, shuffle собирает все единички по словам, reduce суммирует их в `(слово, N)`. Сила модели в том, что ты пишешь только две чистые функции, а распараллеливание на тысячи машин, отказоустойчивость и пересылка данных — забота фреймворка (YT, Hadoop, Spark).

**Статические vs динамические таблицы:**

- **Статические** — иммутабельные таблицы для аналитики. Записал и забыл; перезаписать можно только целиком (или новую партицию). Хранятся как чанки на data nodes, читаются батчами на тысячах exec-нод. Это «холодные» данные — логи, выгрузки, фичи для ML.
- **Динамические** — мутабельные таблицы с точечными операциями: insert/update/delete/lookup по ключу за миллисекунды. Обслуживаются tablet nodes, под капотом LSM-tree. Это «горячие» данные — состояние приложения, профили, счётчики.

**YQL vs CHYT vs SPYT** — три SQL-движка поверх YT, заточенные под разные задачи:

- **YQL** — родной язык YT (диалект SQL + расширения). Компилируется в MapReduce-операции на exec-нодах. Сильная сторона — массивные ETL и аналитика по терабайтам, можно встраивать UDF на Python/C++.
- **CHYT** — ClickHouse, читающий данные YT как свой storage. Заточен под быстрые интерактивные аналитические запросы (секунды, не часы) — типичные дашборды, ad-hoc исследования.
- **SPYT** — Apache Spark поверх YT. Нужен когда у тебя уже есть Spark-пайплайны (особенно ML на PySpark/Scala) и хочется их гонять на данных YT.

Грубо: YQL — тяжёлый ETL, CHYT — быстрая аналитика, SPYT — Spark-совместимость.

---

**Статические vs динамические таблицы:**

Грубо: статические — «архив, читаем целиком толпой» (логи за вчера, фичи для обучения модели). Динамические — «живая БД, читаем по ключу» (профиль пользователя 42, счётчик кликов сейчас).

**YQL vs CHYT vs SPYT:**

Грубо: YQL — «обработай мне петабайт за ночь», CHYT — «открой дашборд и не тормози», SPYT — «у меня уже есть PySpark-код, пусть работает на YT».

---

Партиция — это логический кусок таблицы, обычно по диапазону какого-то ключа (чаще всего по дате). Например, лог событий хранится как `//logs/events/2026-05-01`, `//logs/events/2026-05-02` и т.д. — каждая дата это отдельная таблица-партиция, а сверху директория, которую ты воспринимаешь как «одну большую таблицу за всё время».
