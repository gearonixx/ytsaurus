
Это набор констант-сентинелов типа `TTimestamp` (64-битное беззнаковое), которые задают не конкретный момент времени, а _режим чтения_ — какую версию данных вернуть при запросе.

`NullTimestamp` (0) — неинициализированный/невалидный таймстемп, заглушка.

`SyncLastCommittedTimestamp` — читать последнюю закоммиченную версию строго сериализуемо: если в этот момент идёт конкурентная запись, чтение заблокирует строку и подождёт, чтобы гарантированно не пропустить ничего закоммиченного.

`AsyncLastCommittedTimestamp` — то же «последнее закоммиченное», но без блокировок: быстро, но может не увидеть часть параллельных коммитов (нестрогая гарантия).

`AllCommittedTimestamp` — вернуть все версии, закоммиченные на момент создания читателя; используется для служебных операций вроде flush и compaction, где нужны все версии значения, а не одна.

Обрати внимание на сами числовые значения: верхняя граница «обычных» таймстемпов — `0x3fffffffffffff00`, а эти сентинелы сидят прямо над ней (`...ff01`, `...ff03`, `...ff04`), то есть намеренно вынесены за пределы диапазона реальных временных меток, чтобы их нельзя было спутать с настоящим коммит-таймстемпом.

---

Каждая запись в динамическую таблицу идёт через транзакцию. Транзакция получает коммит-таймстемп в момент успешного коммита, и все строки, которые она записала, помечаются этим таймстемпом как их версия. Старые версии строки не затираются — хранится несколько версий с разными таймстемпами (отсюда multi-version concurrency control). При чтении ты указываешь таймстемп, и движок отдаёт ту версию, которая была актуальна на этот момент — это даёт consistent snapshot без блокировок читателей.
