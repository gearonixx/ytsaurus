
**Deployment** — контроллер, который держит N одинаковых stateless-подов живыми и умеет их обновлять. Ты пишешь «хочу 3 пода с образом nginx:1.25» — Deployment создаёт 3 пода, упал один → поднял новый, поменял образ на 1.26 → постепенно (rolling update) подменяет старые поды новыми по одному, при поломке откатывает.

---

**CRD (Custom Resource Definition)** — регистрирует в Kubernetes новый тип объекта со схемой. После CRD `Ytsaurus` API-сервер принимает YAML с `kind: Ytsaurus` так же, как нативные `Pod`/`Deployment`. Сам по себе ничего не делает — это только описание формы данных.

---

**PVC (PersistentVolumeClaim)** — это запрос пода к Kubernetes: «выдели мне постоянный диск на 5 ГБ». По умолчанию контейнеры эфемерные — что записал на их файловую систему, исчезает при рестарте. Для stateful-вещей (мастер YT с метаданными, data-ноды с чанками) это смерть — рестарт пода = потеря данных. PVC решает: Kubernetes выделяет под капотом **PersistentVolume** (реальный том — кусок диска на ноде, EBS в AWS, сетевое хранилище), монтирует его в под по указанному пути, и при пересоздании пода тот же том прилетает обратно.

---

Да, это та же идея: «отдельное хранилище, которое переживает контейнер/под». Docker volume монтируется в контейнер; PVC монтируется в под. Разница — в Kubernetes это абстракция: PVC говорит «хочу 5 ГБ», а Kubernetes сам решает, откуда взять (локальный диск ноды, облачный EBS, сетевой NFS), и умеет переносить тот же том на другую ноду, если под переехал.

Отличие от StatefulSet: подам Deployment'а пофиг на идентичность и состояние — они взаимозаменяемые, имена вида `ytsaurus-ui-7b469d5cc8-596sf` (рандомный хеш), общих дисков нет. Используется для stateless-сервисов: веб-морды, API, фронтов. У тебя в кластере так задеплоены `ytsaurus-ui-deployment-...` и `strawberry-controller-...` — UI и контроллеру не нужно помнить «кто я и где мои данные», им хватает «я просто один из реплик».
