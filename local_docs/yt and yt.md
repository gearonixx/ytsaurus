
Это верхушка дерева `yt/yt` — основной C++-монорепозиторий YTsaurus. Кратко по каждой папке:

`core` — фундамент: акторная модель, конкурентность, YSON, логирование, сериализация, базовые примитивы. От него зависит почти всё.

`ytlib` — клиентская/протокольная библиотека уровнем выше core: реализация работы с чанками, схемами таблиц, transaction client, RPC к мастеру/нодам. То, что мы разбирали (`TTransactionListener`, `TRspExecuteBatch`) — отсюда.

`client` — публичное клиентское API (`IClient`, `ITransaction`), то что использует прикладной код для общения с кластером.

`server` — собственно сервисы кластера: мастер, ноды (data/exec), планировщик, прокси. Тяжёлая бизнес-логика.

`library` — переиспользуемые утилитарные библиотеки, не специфичные строго для YT-ядра.

`orm` — объектная модель/слой над хранением (Object-Relational-подобный доступ к сущностям).

`flow` — стрим-процессинг подсистема (потоковые вычисления).

`python` — Python-обёртки и биндинги, клиент для питона.

`tools` / `scripts` — утилиты командной строки и вспомогательные скрипты сборки/эксплуатации.

`tests` — тесты (интеграционные/функциональные сверх юнит-тестов рядом с кодом).

`benchmarks` — бенчмарки производительности.

`experiments` — экспериментальный/прототипный код, не прод.

`gpuagent` — агент для GPU-нод (управление GPU-ресурсами на узлах).

`contrib` — сторонние зависимости (vendored third-party).

`packages` — описания пакетов/дистрибутивов для сборки артефактов.

`build` — артефакты/конфигурация сборки (генерится, не исходники).

Файлы `CMakeLists.*` (на платформу) и `ya.make`/`ya_check_dependencies.inc` — две системы сборки: CMake (открытый build) и внутренний `ya` (Яндексовый), описания зависимостей модуля.
