**UnversionedTable** — обычная статическая таблица. У ячеек нет версий и таймстемпов: каждая строка существует в одном-единственном состоянии. Читается как плоский набор строк. Поэтому в твоём логе `Timestamp: 0` и `RetentionTimestamp: 0` — эти поля для такого источника просто не работают, читать «на момент времени T» нечего, версия одна.

`Foreign` помечает источник как «чужой» — вспомогательный вход для **join'а на стороне чтения**, а не основную таблицу.

- **`Foreign: false` (дефолт) — это основной вход. Так в твоём логе: обычное полное чтение одной таблицы, никакого join.**
- **`Foreign: true` — это foreign-сторона: данные читаются не сами по себе, а как справочная таблица, к которой джойнятся ключи основного входа. Шедулер/ридер обращается с ней иначе (другая стратегия чте**


`Foreign: false` = это та таблица, **по которой идём** (левая, ведущая). `Foreign: true` = это таблица, **которую подтягиваем** к ней по ключу (правая, lookup-сторона).

В твоём логе один источник и `Foreign: False` → join'а нет вообще, просто читается одна таблица напрямую.

## Path

Ты дал путь типа `//home/...`, YT перед чтением заменил его на стабильный id таблицы. `#` = «адрес по id». Путь может меняться, id — нет, поэтому дальше таскают id.

Ты обращаешься к таблице по нормальному пути типа `//home/.../table`. Но прежде чем читать, YT резолвит этот путь через мастер в **object id** таблицы (её внутренний «паспорт»). Префикс `#` как раз и означает «это адресация по object id, а не по человекочитаемому пути».

Но это ничего не меняет: строка `"//home/.../table"` и строка `"#1-7a1-10191-1e7c02bb"` — обе валидные значения `TYPath`, просто разный формат содержимого. YT положил в эту строку не исходный человекочитаемый путь, а id-форму после резолва. Тип строковый, а вот что именно лежит в строке — решает код, который её заполняет.

---

**ObjectId — внутренний идентификатор таблицы в YT, её «паспорт».**

Это то, во что резолвится путь (тот самый `1-7a1-10191-1e7c02bb` из лога).

 IClientPtr client — умный указатель на native-клиента YT (NApi::NNative::IClient). Через него берётся соединение, мастер-канал, токены аутентификации и т.д. Грубо — «откуда мы вообще ходим в кластер».
  - NApi::EMasterChannelKind readFrom — enum, куда конкретно идти за чтением в реплицированной мастер-ячейке. Варианты: Leader (свежие данные, но грузит лидера), Follower (с реплики, чуть отстаёт), Cache
  (через master cache, ещё дешевле, но ещё стейл), MasterCache/MasterSideCache и т.п. Просто стратегия консистентность-vs-нагрузка.
  - TCellTag cellTag — идентификатор конкретной мастер-ячейки (cell). В YT мастер шардирован: есть primary cell и несколько secondary, у каждого свой cellTag (число). Объекты «приписаны» к ячейкам, и идти за
  их метаданными нужно именно в нужную. Если InvalidCellTag — обычно подразумевается primary. 
  - TStickyGroupSizeCachePtr stickyGroupSizeCache — кеш для механизма «sticky groups» в Object Service. Когда мастер-фолловеров несколько, клиент старается слать связанные запросы (одна группа = одна
  YPath-операция, например, fetch + locate чанков) на тот же фолловер, чтобы поймать его локальный кеш и не нарваться на гонку «лидер опередил фолловера». Этот кеш хранит, какого размера sticky-группу
  применять к каким запросам. Может быть nullptr — тогда фича просто не используется.

 - Конфиг/инфра:
  GetOptions() — настройки клиента (юзер, токен, таймауты);
  GetNativeConnection() — соединение с кластером (через него дальше достаются все ячейки/каналы);
  GetTransactionManager() — менеджер транзакций;
  GetCounters() — счётчики метрик клиента;
  GetFunctionRegistry(), GetFunctionImplCache() — UDF для query-движка.
  - Каналы (низкоуровневые «трубы» к разным частям кластера):
  GetMasterChannelOrThrow(kind, cellTag) — RPC-канал к мастеру нужной ячейки и нужной свежести (Leader/Follower/Cache);
  GetCellChannelOrThrow(cellId) — канал к конкретной Hydra-ячейке (tablet/chaos);
  GetCypressChannelOrThrow(...) — аутентифицированный канал именно для Кипариса;
  GetSchedulerChannel() — канал к шедулеру;
  GetChannelFactory() — фабрика каналов к нодам.
  - Транзакции:
  AttachNativeTransaction(...) — подцепиться к уже существующей транзакции по её ID.
  - Прикладное:
  LockNodeDetailed(...) — лок узла в Кипарисе с расширенным ответом (нужно операциям/контроллерам);
  SyncAlienCells(...) — синк информации о «чужих» chaos-ячейках;
  DoesOperationsArchiveExist() — есть ли в кластере архив операций;
  IssueSpecificTemporaryToken / IssueTemporaryToken / RefreshTemporaryToken — выпуск и продление временных токенов от имени пользователя.
